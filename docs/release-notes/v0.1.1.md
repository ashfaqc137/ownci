A small fix release: `ownci uninstall` now cleans up after an install that was never set up.

## Install

```bash
curl -fsSL https://sparshlabs.com/ownci/install.sh | sh
```

The script checks the archive against `SHA256SUMS` and installs `ownci` into `~/.local/bin`.
Set `OWNCI_VERSION=v0.1.1` to pin this version. The archives carry GitHub build-provenance
attestations: `gh attestation verify ownci_v0.1.1_linux_<arch>.tar.gz --repo ashfaqc137/ownci`.

## Fixed

- `ownci uninstall --purge` with no runner set up (installed, maybe ran `doctor` or `status`,
  never `setup`) printed "Nothing to uninstall" and kept the data directory. It now removes it,
  with the same safety rules as before: only a directory with OwnCI's marker, only OwnCI's own
  files, and anything else is kept and listed.
- Leftover logs and state of a runner whose directory was deleted by hand no longer block the
  purge. A runner that still holds its lock is left alone.
- `status`, `logs` and `stop` no longer create a missing data directory, so `ownci status` after
  a purge does not bring it back.
- After a purge, the summary prints the command to remove the `ownci` binary itself. OwnCI never
  deletes its own binary.

To remove OwnCI completely: `ownci uninstall --unregister --purge`, then `rm ~/.local/bin/ownci`.
