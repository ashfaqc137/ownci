The first release of OwnCI: a small CLI that turns your Linux or WSL2 machine into a
GitHub Actions self-hosted runner for one repository, where every job runs inside a
Docker container. OwnCI does not implement CI itself. It downloads, verifies, registers,
supervises and cleans up the official [`actions/runner`](https://github.com/actions/runner).

## Install

```bash
curl -fsSL https://sparshlabs.com/ownci/install.sh | sh
```

The script checks the archive against `SHA256SUMS` and installs `ownci` into `~/.local/bin`.
Set `OWNCI_VERSION=v0.1.0` to pin this version, or `OWNCI_INSTALL_DIR` to install elsewhere.
To install by hand, download `ownci_v0.1.0_linux_<arch>.tar.gz` and `SHA256SUMS` below, then:

```bash
sha256sum -c --ignore-missing SHA256SUMS
tar -xzf ownci_v0.1.0_linux_<arch>.tar.gz && install -m 0755 ownci ~/.local/bin/ownci
```

The archives carry GitHub build-provenance attestations:
`gh attestation verify ownci_v0.1.0_linux_<arch>.tar.gz --repo ashfaqc137/ownci`.

Then run `ownci doctor` and `ownci setup --repo owner/name`. The
[README](https://github.com/ashfaqc137/ownci#quick-start) has the full guide.

## What's in it

- `setup`, `start`, `stop`, `status`, `logs`, `doctor`, `uninstall` and `version`.
- **Host mode** (the default): the runner runs on your machine. Jobs must declare
  `container:`, and jobs without one are rejected.
- **Container-runner mode** (`setup --mode container-runner`): the runner itself runs in a
  digest-pinned `ghcr.io/actions/actions-runner` container, recreated for every job, so
  unchanged workflows without `container:` work too.
- The pinned runner (2.338.0) is checksum-verified before extraction.
- After every job a hook wipes the workspace, `_actions` and `_tool` in a throwaway,
  network-less container.
- Public repositories are refused unless you pass `--allow-public-repo`.
- Your GitHub token is never stored, and tokens are redacted from the logs.
- Several repositories can run side by side, one data directory per repository. Per-developer
  labels let one workflow file serve a whole team.

## Platforms

| Platform | Status |
|---|---|
| WSL2 + Docker Desktop, amd64 | Tested end to end against real GitHub ([acceptance record](https://github.com/ashfaqc137/ownci/blob/main/docs/acceptance.md)) |
| Native Linux (Docker Engine), amd64 | Shipped, expected to work, not tested yet |
| Linux / WSL2, arm64 | Shipped, expected to work, not tested yet |
| Windows | Use the Linux binary inside WSL2. Native Windows is not supported |
| macOS | Not supported yet |

## Known limitations

- **Trusted workflows only.** The official runner mounts the Docker socket into job
  containers, so a job can control your Docker daemon. The container is a guard against
  accidents, not against hostile code. Read the README's
  [Security and trust model](https://github.com/ashfaqc137/ownci#security-and-trust-model).
- In container-runner mode, a job without `container:` can read the runner's registration
  credentials while it runs.
- Container-runner mode relies on `run.sh --once`, which the runner marks as deprecated.
- Runner self-update inside the runner container has not been exercised yet, because no
  newer runner release existed during testing.
- After a supervisor is killed with `kill -9`, the next `start` can take about a minute to
  reconnect while GitHub expires the old session. `status` may keep showing that conflict
  as *Last error* after it recovers.
- One job at a time per data directory. There is no systemd service or start on boot, and
  OwnCI does not install Docker for you.
